Architecture

media-core

The app creates the configured client and provides it to a wrapper. Wrappers coordinate framework state and delegate data operations to core. Core does not import React, React Native, DOM APIs, or UI packages.

Implementation note

The assessment requested pure TypeScript for media-core. The repository implementation is JavaScript with JSDoc. No package in this SDK site claims to be implemented in TypeScript.

02 · INSTALL

Install in this workspace

These packages are currently private npm workspaces, not published registry packages. From the repository root, install the workspace dependencies:

npm install

Import from each package's public root. The root exports point to each package's src/index.js.

03 · CORE CLIENT

Create a client

Supply the Pexels API key when creating a client. Optional cacheTtlMs defaults to 30 seconds; use 0 to disable the in-memory GET cache. fetchImpl can be injected for tests or custom runtimes.

import { createMediaClient } from '@foto-owl/media-core';

const client = createMediaClient({
  apiKey: appConfig.pexelsApiKey,
  cacheTtlMs: 30_000,
});

The client sends the credential using the Pexels Authorization header. Do not hardcode or commit a real key. In the Vite web app, the checked-in entrypoint reads import.meta.env.VITE_PEXELS_API_KEY; Vite exposes prefixed variables to browser code.

04 · REQUESTS

Search photos and videos

Photos are the default. Use type: 'videos' for videos. Each response has items, page, perPage, totalResults, hasNextPage, nextPageUrl, and previousPageUrl. Items retain Pexels fields and add kind (image or video) and mediaType (photo or video).

const photos = await client.search('mountain lake', {
  page: 1,
  perPage: 24,
});

const videos = await client.search('mountain lake', {
  type: 'videos',
  page: 1,
  perPage: 24,
});

Pagination

Pages are one-based. The default is page 1 with 15 items; perPage accepts 1–80. Advance while hasNextPage is true.

if (photos.hasNextPage) {
  const nextPhotos = await client.search('mountain lake', {
    page: photos.page + 1,
    perPage: photos.perPage,
  });
}

Other supported scalar options, such as orientation, are passed as query parameters. Curated photos use client.getCurated(options); with { type: 'videos' } it returns popular videos. client.getById(id, { type }) retrieves one item.

const curatedPhotos = await client.getCurated({ perPage: 12 });
const popularVideos = await client.getCurated({ type: 'videos', perPage: 8 });
const photo = await client.getById(2014422);
const video = await client.getById(2499611, { type: 'videos' });

Cache and duplicate requests

Successful GET responses are cached in memory per client for 30 seconds by default. Set cacheTtlMs: 0 to turn caching off, or call client.clearCache(). Concurrent requests with the same endpoint and parameters reuse an in-flight promise; errors are not cached.

05 · REACT

@foto-owl/media-react

This package exports MediaProvider, useMediaClient, useMediaSearch, useMediaCurated, useMediaItem, useMediaEvent, useMediaViewEvent, and useMediaDownloadEvent. It supplies context and request-state lifecycle; it does not create clients or duplicate Pexels logic.

import { MediaProvider } from '@foto-owl/media-react';

<MediaProvider client={client}>
  <App />
</MediaProvider>

useMediaSearch({ query, page, perPage, type }) returns results, pagination, loading, error, search, and refetch. Empty queries do not request data. The hook forwards filters such as type: 'videos' to core.

const { results, pagination, loading, error, refetch } = useMediaSearch({
  query,
  page: 1,
  perPage: 24,
  type: 'videos',
});

if (error) return <button onClick={() => refetch()}>Retry</button>;
if (loading) return <p role="status">Loading…</p>;
if (results.length === 0) return <p>No videos found.</p>;

useMediaCurated({ page, perPage, type }) loads curated photos by default or popular videos when type is videos. useMediaItem(id, options) returns data, loading, error, and refetch.

06 · REACT NATIVE-FACING ADAPTER

@foto-owl/media-native

This is a lightweight React provider/hooks adapter, not a full React Native application or native build setup. Its public exports are MediaNativeProvider plus useMediaClient, useMediaSearch, useMediaCurated, useMediaItem, and event hooks.

import { createMediaClient } from '@foto-owl/media-core';
import {
  MediaNativeProvider,
  useMediaSearch,
} from '@foto-owl/media-native';

const client = createMediaClient({ apiKey: appConfig.pexelsApiKey });

function SearchScreen() {
  const { results, loading, error, pagination } = useMediaSearch({
    query: 'waterfall', page: 1, perPage: 20,
  });
  // Render using app-owned React Native primitives.
  return null;
}

function NativeApp() {
  return (
    <MediaNativeProvider client={client}>
      <SearchScreen />
    </MediaNativeProvider>
  );
}

Wrap native screens in <MediaNativeProvider client={client}>. The app owns rendering, API-key configuration, and application-specific decisions.

07 · EVENTS

View and download events

client.events supports on, off, and emit for view and download. Payloads include mediaId and mediaType; url, source, and app-owned metadata are optional. The app emits events when an action occurs; the SDK does not infer views or downloads.

const unsubscribe = client.events.on('view', (payload) => {
  console.info('Viewed', payload.mediaId);
});

client.events.emit('view', {
  mediaId: item.id,
  mediaType: item.mediaType,
  source: 'gallery',
});

unsubscribe(); // Or client.events.off('view', listener)

The emitter has a default console listener. React and native wrapper event hooks subscribe and clean up automatically; they do not emit.

08 · ERRORS

Handle SDK failures

Core throws the exported MediaSdkError with a stable code and optional HTTP status. Common codes include MISSING_API_KEY, INVALID_ARGUMENT, NETWORK_ERROR, HTTP_ERROR, and INVALID_RESPONSE. Error messages do not expose the API key or raw response body.

import { MediaSdkError } from '@foto-owl/media-core';

try {
  const page = await client.search('forest');
} catch (error) {
  if (error instanceof MediaSdkError) {
    console.error(error.code, error.status, error.message);
  }
}

Data hooks expose errors and loading separately. They do not implement automatic retry or network-layer cancellation; the consuming app chooses the retry and display behavior.
