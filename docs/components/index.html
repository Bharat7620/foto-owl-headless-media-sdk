Your design system.

01 · COMPONENT CONTRACT

Render props and prop-getters

Each component requires a function as children. The function receives state, data, callbacks, and prop-getters. Spread each getter result onto the matching consumer-owned element so behavior, refs, and accessibility attributes are retained. Getter props can be customized with an object argument; custom event handlers are composed with the component behavior.

<MediaGrid items={items}>
  {(grid) => (
    <div {...grid.getRootProps({ className: 'gallery' })}>
      {/* Consumer renders the content and CSS hooks. */}
    </div>
  )}
</MediaGrid>
Data boundary

These packages do not fetch, import the SDK or wrappers, or contain Pexels logic. Normalize provider-specific URLs in your app before rendering.

02 · RESULTS

MediaGrid

Props: items, loading, hasMore, onLoadMore, onItemClick, and optional label. Its render API provides items, state/callbacks, and getRootProps, getRowProps, getItemProps, and getLoadMoreProps. It accepts photos and videos without filtering them.

This example follows the real consumer structure in apps/web/src/components/MediaGallery.jsx:

import { MediaGrid } from '@foto-owl/media-ui-react';

function Gallery({ items, loading, hasMore, loadMore, selectItem }) {
  return (
    <MediaGrid items={items} loading={loading} hasMore={hasMore}
      onLoadMore={loadMore} onItemClick={selectItem}>
      {(grid) => (
        <div {...grid.getRootProps({ className: 'media-grid' })}>
          {grid.items.map((item, index) => (
            <button key={`${item.id}-${index}`}
              {...grid.getItemProps({ item, index, className: 'media-card' })}>
              {item.alt || item.title || `Media ${index + 1}`}
            </button>
          ))}
        </div>
      )}
    </MediaGrid>
  );
}

The React grid getter supplies keyboard activation for Enter and Space. Load-more activation is disabled while loading or when there are no more items; connect onLoadMore to app pagination or an app-owned scroll observer. The component itself does not implement infinite scrolling.

03 · SELECTED MEDIA

MediaLightbox

The React component is controlled by item, optional open (defaults to item presence), and onClose. Its render API gives item, open, mediaType, isVideo, close, and getters for dialog, close button, image, and video elements.

Real app composition: App.jsx passes selected state to the component; MediaLightboxView.jsx renders the dialog and media:

<MediaLightbox item={selected} open={Boolean(selected)}
  onClose={() => setSelected(null)}>
  {(api) => (
    <div {...api.getDialogProps({ className: 'lightbox-dialog' })}>
      <button {...api.getCloseButtonProps({ className: 'lightbox-close' })}>
        Close
      </button>
      {api.isVideo
        ? <video {...api.getVideoProps({ src: mediaSrc(api.item) })} />
        : <img {...api.getImageProps({ src: mediaSrc(api.item) })} />}
    </div>
  )}
</MediaLightbox>

The actual app calls its provider-aware source helper from apps/web/src/utils/media.js. This matters for Pexels photos, whose src value is an object of size URLs: the component's generic helper only recognizes conventional string src or url. Keep that adaptation in the app.

04 · VERTICAL MEDIA

MediaReelSwiper

Accepts items, optional controlled activeIndex, onActiveChange(index, item), and optional label. Render props include items, activeIndex, activeItem, getScrollerProps, and getSlideProps. Scroll position detects the nearest slide; the app owns snap CSS.

This mirrors the actual apps/web/src/components/ReelsView.jsx scroller/slide composition:

<MediaReelSwiper items={videoItems} activeIndex={active}
  onActiveChange={(index, item) => { setActive(index); onView(item); }}>
  {(reel) => (
    <div {...reel.getScrollerProps({ className: 'reel-scroller' })}>
      {reel.items.map((item, index) => (
        <section key={item.id}
          {...reel.getSlideProps({ item, index, className: 'reel-slide' })}>
          <video src={mediaSrc(item)} controls={false} playsInline />
        </section>
      ))}
    </div>
  )}
</MediaReelSwiper>

The app stylesheet defines vertical overflow and scroll-snap-type on the scroller plus scroll-snap-align on slides. The package does not include CSS.

05 · NATIVE RENDERING CONTRACT

@foto-owl/media-ui-native

The native package exports the same three component names, but its prop-getters target React Native primitives and use native interaction/accessibility fields. It does not depend on React Native build infrastructure or choose a video player.

MediaGrid

Render getters on View and Pressable. Item activation is onPress; load-more props expose disabled/busy state.

MediaLightbox

Render the modal getter on Modal. It provides visibility and request-close behavior; supply a native video player yourself.

MediaReelSwiper

Render the scroller getter on a scroll view. It supplies horizontal: false, pagingEnabled, scroll handlers, and scrollToIndex(index, animated).

import { ScrollView, View } from 'react-native';
import { MediaReelSwiper } from '@foto-owl/media-ui-native';

<MediaReelSwiper items={items} onActiveChange={setActiveIndex}>
  {({ items, getScrollerProps, getSlideProps }) => (
    <ScrollView {...getScrollerProps()}>
      {items.map((item, index) => (
        <View key={item.id} {...getSlideProps({ item, index })} />
      ))}
    </ScrollView>
  )}
</MediaReelSwiper>

This native example follows the component contract documented in packages/media-ui-native/README.md. The repository has no full native application; consumers must provide native primitives, styling, and playback.

06 · ACCESSIBILITY & STYLING

Semantics stay in the markup

  • Spread getter props on the actual grid, item, dialog, control, scroller, or slide element.
  • Use buttons or pressables for actions; provide useful labels and image alternative text.
  • Keep getter refs, event handlers, roles, ARIA attributes, and accessibility state when adding custom props.
  • Render loading and empty states in the app and expose busy/disabled states through the grid props.
  • Implement layout, colors, animations, overlays, image sizing, and scroll snapping in consumer CSS/layout.
  • Choose the media URL field and any platform-specific video player in the consuming app.
No baked-in visual design

Both component packages provide behavior and prop-getters. They ship no CSS or design system.

All packages are JavaScript. media-core uses JSDoc for public API/data documentation, although the assessment requested pure TypeScript; this is a known implementation deviation.

07 · PUBLISH AS STATIC SITES

Deploy independently on Vercel

Each documentation site is plain static HTML and CSS with no build-time framework or dependency installation. Create separate Vercel projects from the repository, set the project Root Directory to docs/components, choose the Other preset, leave the build command empty, and use . as the output directory. Repeat with docs/sdk for the SDK site. This matches Vercel's guidance for static HTML/CSS sites with no build step; see Vercel build configuration.

There are no deployment URLs configured in this repository. A project can also be served locally with any static file server, or opened directly as index.html.
